# Enterprise-RAG v2.0: Architecture Plan (Future)

Este documento describe la arquitectura y funcionalidades planificadas para la versión 2.0 del sistema Enterprise-RAG, enfocándose en seguridad, escalabilidad y gestión multi-entidad.

## 1. Visión General
La v2.0 transformará el sistema de un motor de búsqueda agnóstico a una **plataforma empresarial segura multi-tenant**. El objetivo principal es garantizar que los datos estén aislados por departamento y accesibles solo mediante autenticación y permisos granulares.

## 2. Nuevos Componentes Core

### 2.1 Módulo de Identidad y Acceso (IAM)
* **Autenticación (AuthN):** Integración con proveedores OAuth2/OIDC (Google Workspace, Microsoft Entra ID).
* **Autorización (AuthZ):** Implementación de RBAC (Role-Based Access Control).
* **Base de Datos de Usuarios:**
    * Tabla `Users`: ID, email, provider_id, created_at.
    * Tabla `Roles`: 'admin', 'editor', 'viewer'.
    * Tabla `Departments`: 'Engineering', 'HR', 'Finance', etc.
    * Relación `UserDepartments`: Mapeo N:N entre usuarios y departamentos accesibles.

### 2.2 Motor de Ingesta Avanzado
* **Soporte Multi-fuente:** Capacidad para observar y procesar múltiples directorios simultáneamente.
* **Metadata Enriquecida:**
    * Cada documento ingerido se etiquetará obligatoriamente con `department_id` y `owner_id`.
    * Validaciones de esquema en tiempo de ingesta.
* **Pipeline de Ingesta:**
    * Cola de tareas para procesamiento asíncrono masivo (ficheros grandes o múltiples carpetas).

## 3. Cambios en la Búsqueda (RAG)
* **Filtrado Estricto de Contexto:**
    * El `QueryEngine` inyectará filtros de metadatos automáticos basados en el usuario autenticado (JWT).
    * `filter: { department: { $in: user.allowed_departments } }`
* **Auditoría de Consultas:**
    * Registro de quién preguntó qué y cuándo (Compliance logging).

## 4. API & Frontend Roadmap

### Backend (FastAPI)
* Middleware de Autenticación para validar Bearer Tokens.
* Endpoints administrativos para gestión de usuarios y permisos.
* Refactor de `/ingest` para aceptar `department_target`.

### Frontend
* Pantalla de Login (redirección OAuth).
* Gestión de Sesión (JWT storage).
* Dashboard Administrativo para gestión de fuentes de datos.
* UI de carga de archivos con selector de departamento destino.

## 5. Estrategia de Migración
1. **Schema Update:** Actualizar esquemas de Qdrant y FalkorDB para incluir nuevos campos de metadata.
2. **Data Backfill:** Script para asignar un departamento "Legacy" o "General" a los documentos existentes.
3. **Cutover:** Despliegue de los servicios de Auth antes de abrir el acceso multi-user.
